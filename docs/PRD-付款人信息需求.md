## 1. 背景与问题

当前中古优品 ERP 在订单付款环节存在「**实际打款人 ≠ 客户实名**」的合规与对账风险:

- 客户用家人/朋友的银行卡代付,银行回单上的真实姓名与平台注册客户实名不一致;
- 部分高客单(LV/劳力士/百达翡丽 等数万到几十万)订单缺乏白名单与凭证机制,事后难溯源;
- 出现「客户已支付,但本平台无法判断该笔款是否合规」的灰色区域,常需人工电话核实;
- 历史已经发生过「打款人非本人 → 退款/资金拘留 → 客户投诉」的工单。

业务目标:在不增加 C 端付款流程负担的前提下,**自动识别风险款项 → 系统挂起 → 管理员后台处理 → 沉淀客户级白名单**,形成闭环。

## 2. 目标与非目标

### 2.1 目标
1. 银行回调入账时,系统自动校验「打款人姓名 + 银行卡」与客户实名/客户已登记的付款人信息,不匹配则**自动挂起付款单**;
2. 提供 3 条标准处理动作:**人工通过 / 加白通过(添加付款人信息后自动通过)/ 原路退款**,辅以**暂时挂起观察**作为暂存态;
3. 客户级**付款人信息(白名单)**可视、可管理:支持新增 / 编辑 / 失效 / 恢复 / 删除,带凭证图片与授权委托书附件;
4. 客户**重新支付** 且新打款人匹配已加白记录时,历史挂起款项自动「**通过加白处理**」归档,不再人工干预;
5. 所有处理动作落操作日志,可追溯 ;权限默认仅 admin / boss / 财务可见挂起单 actions。

### 2.2 非目标(本期不做)
- 不做 C 端付款界面改造,不阻断客户付款;
- 不接入第三方 KYC,不做身份证 OCR;
- 不做付款人风险评分模型,仅做规则校验。

## 3. 名词

| 术语 | 含义 |
| --- | --- |
| 付款单(Payment) | 一笔银行回单对应的入账记录,从属于订单。一个订单可有多个付款单(多次支付 / 多次挂起) |
| 挂起付款单 | 因校验未过被系统自动暂停的付款单,status = pending(待处理) |
| 付款人信息 | 客户级的可信打款人白名单条目:姓名 + 银行卡(可多张) + 凭证附件 + 授权委托书 |
| 加白通过 | 添加付款人信息 → 同时把当前挂起单自动放行,订单流转下一节点 |
| 暂时挂起观察 | 把挂起付款单标记为「on_hold」暂存态,30 天内可切换为退款 |
| 原路退款 | 不可撤销的真实资金动作,原路退回客户原打款账户 |
| 加白处理(归档) | 历史挂起款项因后续被加入白名单,系统自动判定为合规并归档 |

## 4. 用户角色与场景

### 4.1 角色

| 角色 | 权限范围 |
| --- | --- |
| 销售 | 只读订单/付款单,可在客户主页提交加白申请(不直接处理) |
| 管理员 / 财务(admin/boss) | 完整处理挂起单 / 加白 / 退款 / 编辑付款人信息 |
| 客户(C 端) | 收到挂起通知,可重新支付;不接触本后台 |

### 4.2 典型场景

**S1 · 第一次代付被挂起**
> 客户「张三」下单 ¥56,800 LV 包,其家人「赵伟」用招商银行卡代付。系统识别打款人为「赵伟」,与「张三」实名不符 → 自动挂起 → 管理员王梅在订单详情看到红色挂起警示 → 选择「加白通过」→ 上传授权委托书 + 关系凭证 → 提交后挂起单自动放行,订单流转「待卖家发货」。

**S2 · 客户多次重新支付仍非本人**
> 同一订单先后被「赵伟」「王伟」打款,产生 2 条挂起付款单,聚合到同一订单详情。

**S3 · 暂时挂起观察 → 后续加白归档**
> 「陈某」打款被挂起,管理员选「暂时挂起观察」(无任何资金动作)。两周后客户重新支付订单成功并把「陈某」加入付款人信息;系统检测到历史挂起记录的打款人匹配新加白记录,**自动标记为「已通过加白处理」并归档**,无需退款。

**S4 · 原路退款**
> 银行回单未识别打款人姓名(未识别),客户也联系不上 → 管理员选择「原路退款」,弹出真实资金动作二次确认。

**S5 · 付款人信息生命周期**
> 客户因家庭原因申请「张前妻」失效;此后该银行卡再来款不再自动通过,需重新走挂起流程。

## 5. 信息架构与导航

```
├─ 订单管理 / 订单列表
│  └─ 订单详情(含「挂起警示条」「付款单 Tab」)
├─ 财务管理 / 待确认款项 [NEW]
│  └─ 待确认款项详情
└─ 客户管理 / 客户列表
   └─ 客户详情(含「付款人信息」卡片区)
```

挂起付款单同时出现在**订单详情**和**待确认款项列表**,数据源为同一条 payment_record。

## 6. 功能详细说明

### 6.1 订单列表

- 顶部 Tab 横排:全部 / 待付款 / 待发货 / 已发货 / 已完成 / 已取消 / **已挂起**(红色突出 + 红色徽标);
- 已挂起 Tab 紧跟「已取消」之后,徽标颜色 `--error` 强调;
- 行内字段:订单号、商品、金额、客户、销售、状态标签、挂起标识、操作链接;
- 操作:查看详情 / 处理挂起(仅 held=true 显示)/ 取消订单(仅 pending_pay)/ 发货 / 查看物流;
- 标签筛选与状态计数实时(`getStatusCount`)。

### 6.2 订单详情 · 挂起警示条

进入 held=true 订单详情时:

- 顶部增加红色挂起警示卡片,展示挂起付款单列表(每笔含 PAY-No / 打款人 / 银行卡 / 金额 / 持续时长 / 挂起原因);
- 每笔挂起单内联 4 个标准动作按钮:**人工通过 / 加白通过 / 原路退款·挂起观察 / 查看校验**;
- 多笔挂起聚合显示,各自独立处理。

### 6.3 4 类标准动作 Modal

| 动作 | Modal | 表单字段 | 提交后效果 |
| --- | --- | --- | --- |
| 人工通过 | modalPass | 通过原因(下拉) + 备注 | 挂起付款单 status → passed;订单流转下一节点 |
| 加白通过 | modalAddPayer | 关系类型(直系/配偶/朋友/对公等) / 付款人姓名 / 身份证 / 银行卡 / 关系凭证(图片) / 授权委托书(PDF 模板下载 + 上传) / 备注 | 同时新增付款人信息 + 挂起单放行 |
| 查看校验 | modalVerify | 展示校验明细:客户实名 / 已登记付款人 / 实际打款人 / 银行卡匹配状态 / 判定结论 | 只读,底部可一键进入「加白通过」 |
| 原路退款 / 挂起观察 | modalFundProcess | 单选:↩ 原路退款 / ⏸ 暂时挂起观察。退款方式需填退款原因 + 二次确认(不可撤销) | 退款 → status: refunded;挂起观察 → status: on_hold(30 天提示) |

### 6.4 财务管理 · 待确认款项列表

- 数据 = 当前活跃挂起付款单(从 ORDERS 派生) + 历史处理记录(refunded / on_hold / whitelist);
- 4 张汇总卡:待处理笔数与金额 / 本周新增 / 同比 / 累计已处理;
- 状态 Tab:全部 / 待处理 / 已退款 / 暂时挂起观察 / 已通过加白处理;
- 筛选:用户 ID / 订单号 / 时间范围;
- 行内操作:与订单详情挂起警示条对齐(人工通过 / 加白通过 / 原路退款·挂起观察 / 查看校验)。

### 6.5 待确认款项详情

- 顶部含金额、客户、打款人、银行卡;
- 处理信息区(状态、处理人、处理时间、退款单号、退款原因);
- 操作日志时间线(从「银行回调入账」→「客户取消本次付款」→「创建退款单」→「资金原路退回」);
- 「客户加白后归档」:对应时间线带「+ 添加付款人信息」事件,链到 PAYER-NNNN 记录。

### 6.6 客户详情 · 付款人信息卡片

- 客户主页新增「付款人信息」卡片区,右上角「+ 添加付款人信息」按钮;
- 每条付款人卡片字段:姓名 + 与客户关系 + 身份证(脱敏)+ 多张银行卡 + 凭证缩略图 + 授权委托书附件;
- 卡片状态:**生效中 / 已失效**(失效卡片置灰、加红角标);
- 操作:编辑 / 失效(生效中卡片) / 恢复 / 永久删除(失效卡片);
- 失效后,该银行卡再来款不再自动通过,会重新进入挂起流程;
- 永久删除需二次确认,删除后凭证与历史不可恢复(但订单日志保留)。

### 6.7 付款人信息凭证

- 凭证图片:支持上传(图片格式),Demo 中仅占位;
- 授权委托书:平台提供 PDF 模板「下载模板 → 客户签字 → 扫描上传」;
- 对公付款人:需上传对公授权书 + 营业执照;
- 附件预览:点击缩略图弹出预览 Modal,支持下载原图 / PDF。

### 6.8 自动「加白后归档」逻辑

触发条件:
1. 历史存在 status=on_hold 的 payment_record;
2. 客户重新支付该订单成功;
3. 重新支付的打款人 + 银行卡被添加到该客户的付款人信息(白名单);

系统动作:
- 把历史 on_hold 的 payment_record status → whitelist;
- 在订单日志与待确认款项详情生成「✓ 本笔款项已通过添加付款人信息(加白)自动归档」事件;
- 不需要人工触发。

## 7. 校验规则与状态机

### 7.1 入账校验流程(伪代码)

```
on bank_callback(payment):
  if payment.payerName == customer.realName
     and payment.bankCard in customer.cards:
       → 直接放行
  else if payment.payerName in customer.payers.activeNames
       and payment.bankCard in customer.payers.activeCards:
       → 直接放行
  else:
       → 创建挂起付款单, status=pending, 写入挂起原因
       → 触发管理员通知
```

### 7.2 付款单状态机

```
pending(挂起) ──┬─→ passed(人工通过)
                 ├─→ whitelist(加白通过 / 加白后归档)
                 ├─→ refunded(原路退款) [真实资金动作,不可撤销]
                 └─→ on_hold(暂时挂起观察) ──→ refunded / whitelist
```

### 7.3 付款人信息状态机

```
active(生效中) ──┬─→ invalidated(已失效) ──┬─→ active(恢复)
                                              └─→ deleted(永久删除)
```

## 8. 数据需求

### 8.1 字段(关键)

**payment_record**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| pay_no | string | PAY-XXXXX |
| order_no | string | 关联订单号 |
| payer_name | string | 银行回单上的打款人姓名(可能为「未识别」) |
| payer_card | string | 银行 + 卡号 |
| amount | decimal | 金额 |
| status | enum | pending / passed / refunded / on_hold / whitelist |
| reason | string | 挂起原因(校验未过的具体描述) |
| paid_at | datetime | 银行入账时间 |
| processed_at | datetime | 处理时间 |
| processor | string | 处理人 |
| process_remark | string | 处理备注 |

**customer_payer(付款人信息)**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| payer_id | string | PAYER-NNNN-NNN |
| customer_id | string | 关联客户 |
| relation | enum | direct(直系)/ spouse / friend / corporate(对公) / other |
| name | string | 付款人姓名 |
| id_card | string | 身份证(脱敏存储) |
| cards | array<string> | 银行卡列表(可多张) |
| attachments | array<file> | 凭证图片 / 委托书 / 营业执照 |
| status | enum | active / invalidated / deleted |
| created_at / invalidated_at / deleted_at | datetime | — |

### 8.2 列表接口字段精简
- list handler 须 strip 大字段(凭证 binary 不进 list),仅 detail 接口返回完整附件 URL。

## 9. 权限

| 操作 | 角色 |
| --- | --- |
| 查看挂起付款单 | admin / boss / 财务 / 销售(只读) |
| 人工通过 / 加白通过 | admin / boss / 财务 |
| 原路退款(真实资金) | admin / boss(财务可发起,需 boss 复核 - 后期开关,本期 admin 即可) |
| 编辑 / 失效 / 恢复 / 删除 付款人信息 | admin / boss / 财务 |

## 10. 流程图(主流程)

```
银行回调入账
    │
    ▼
校验(实名+卡号)
    │
    ├──通过──→ 订单流转(下一节点)
    │
    └──挂起──→ 待确认款项列表 / 订单详情挂起警示
                  │
        ┌─────────┼─────────┬───────────┐
        │         │         │           │
   人工通过   加白通过   原路退款  暂时挂起观察
        │         │         │           │
        ▼         ▼         ▼           ▼
   订单流转   订单流转    资金退回    待后续动作
              + 白名单                  │
                                  客户重新支付
                                  + 加白匹配
                                        │
                                        ▼
                                  自动归档(whitelist)
```

## 11. 验收 Checklist

- [ ] 银行回调后挂起规则正确(实名 + 卡号双匹配)
- [ ] 订单详情同时显示 N 条挂起付款单(N≥2 不串行)
- [ ] 4 类 Modal 表单校验完整,必填项缺失能阻断提交
- [ ] 「加白通过」一次提交后,客户付款人信息表新增 1 条 + 挂起单 status→whitelist
- [ ] 「原路退款」二次确认弹层,确认前不调真实退款接口
- [ ] 「暂时挂起观察」可重新切换为「原路退款」,超 30 天系统仅提示不自动动作
- [ ] 客户重新支付 + 加白后,历史 on_hold 记录自动归档为 whitelist(可不需人工干预)
- [ ] 失效付款人后,同卡号再来款被重新挂起
- [ ] 永久删除付款人需二次确认,删除后订单日志仍可追溯
- [ ] 列表接口不返回凭证 binary;详情接口返回签名 URL
- [ ] 操作日志记录:操作人 / 时间 / 动作 / 备注
- [ ] 权限隔离:销售只读,不能触发 4 类动作
