## 1. 背景与问题

中古优品业务以**奢侈品拍卖直播**为主要 GMV 来源,一场 3 小时直播通常上架 100–200 件,以拍卖出价 + 一口价混合售卖,人工成本高且经营结果差异极大。当前问题:

- 直播结束后没有**统一的场次复盘视图**,主播 / 助手 / 运营各自看零散指标;
- 缺乏**口径一致**的核心指标:支付总额、成本利润率、转化漏斗在不同人口径不一致,引起跨部门数据扯皮;
- 无法在**商品维度**做横向统计:跨场次的「上架 / 加购 / 下单 / 支付」漏斗 + 品牌 / 分类 / 成色筛选;
- 多场对比、TOP 主播 / 助手贡献排名缺位。

业务目标:统一**场次** + **商品** 两个视角,提供从汇总到详情的完整看板,并对每个指标提供**点击查看口径说明**的能力(避免数据口径分歧)。

## 2. 目标与非目标

### 2.1 目标
1. 直播场次列表 + 详情:覆盖单场所有核心经营指标和全链路转化漏斗;
2. 直播商品统计:跨场次的商品维度数据,按品牌 / 分类 / 成色 / 状态等多维筛选;
3. 每个核心指标内联「ⓘ 口径说明」,弹窗解释计算公式与统计边界,数据口径不再扯皮;
4. 列表 / 详情 / 商品三类视图统一在「直播」一级菜单下,支持顶部 Tab 与侧栏二级菜单**双入口同步**;
5. 支持导出本场数据 / 导出商品列表 / 导出统计数据;
6. T+0 实时数据更新,标注更新时间。

### 2.2 非目标(本期不做)
- 不做实时直播控制台(开播 / 推流 / 弹幕),仅做数据呈现;
- 不做 AI 推荐或自动选品;
- 不做主播 KPI 工资核算,仅给排名维度。

## 3. 名词与口径

> 所有口径与 Demo 中 `kpData` 完全一致,以页面内 ⓘ 弹窗为准。

| 指标 | 口径(摘要) |
| --- | --- |
| **支付总额** | 本场已完成下单且已支付的订单实付金额合计,未扣除后期售后 |
| **支付成本** | 已支付商品的成本价合计(建档成本),不含鉴定 / 物流 / 仓储等 |
| **支付利润** | 支付金额 − 支付成本 |
| **成本利润率** | (支付总额 − 支付成本) ÷ 支付成本 × 100%。从成本视角看获利能力,与销售利润率分母不同 |
| **平均成本利润率(跨场)** | Σ(支付利润) ÷ Σ(支付成本)。**按金额加权**,不按场次算术平均 |
| **支付率 / 售出率** | 支付件数 ÷ 上架件数 × 100% |
| **加购** | 被加入购物车或参与出价的商品件数(去重)。拍卖出价 = 自动加购;一口价主动加购 |
| **加购转化率** | 加购件数 ÷ 上架件数 |
| **下单** | 形成订单的件数,含未支付 / 已取消 |
| **下单金额** | 含未支付订单的成交价合计 |
| **客单价(AOV)** | 支付总额 ÷ 付费用户数 |
| **观看人数(UV)** | 进入过本场直播间的去重用户数 |
| **观看人次(PV)** | 累计访问次数,同一用户多次进入累计计算 |
| **互动人数** | 有任意互动(出价 / 加购 / 评论 / 点赞 / 关注 / 分享 / 收藏 / 订阅)的去重用户数 |
| **中拍超时取消** | 中拍后未在支付时限(默认 30 min)完成支付而被系统取消的件数 |

## 4. 用户角色与场景

### 4.1 角色

| 角色 | 关注内容 |
| --- | --- |
| 产品经理 / 运营 | 跨场对比、转化漏斗、品牌 / 分类分布,做选品和场次策划 |
| 直播运营 | 单场详情 / 主播排名 / 助手贡献,做人员调度 |
| 主播 / 助手 | 本场结果回顾、商品出价数据 |
| 财务 / Boss | 支付总额 / 成本 / 利润率(对账与经营汇总) |

### 4.2 典型场景

**S1 · 单场复盘**
> 运营在直播结束 10 分钟内打开「场次列表 → 点击当场行」,看本场支付总额 ¥17,350 / 成本利润率 4.24% / 全链路漏斗 132→107→82→81 → 判断「转化没问题但成本太高,下次选品避开低毛利款」。

**S2 · 跨场对比**
> 运营选中 5 场,点「对比所选」(后续迭代):并列指标对比 → 发现主播 A 的成本利润率显著高于 B → 把 A 排到更高客单场次。

**S3 · 商品维度复盘**
> 进入「直播商品」模块,筛选「品牌=香奈儿 + 分类=箱包 + 时间=本月」→ 看到 1,847 件上架 → 1,084 件支付(58.7%)→ 决策下场加大香奈儿箱包上架占比。

**S4 · 口径质疑**
> 财务问「成本利润率为什么是 4.24% 不是 4.07%」→ 用户点 ⓘ 弹出公式:`(支付总额 − 支付成本) ÷ 支付成本`,清晰看到分母是成本而非售价 → 不需要拉群对账。

**S5 · 待开播预览**
> 列表筛选 Tab「待开播」,2 场未开始,行底色加蓝(预约高亮),操作变成「实时 / 控制台」(本期占位,跳转后续模块)。

## 5. 信息架构与导航

```
直播(一级菜单 / 顶部 Tab 双入口)
├─ 直播场次  ←─ 默认入口
│  ├─ 场次列表
│  └─ 场次详情
└─ 直播商品

```

- 侧栏二级菜单 ↔ 顶部 Tab **状态同步**(切换其一另一处同步高亮);

- 场次详情归属「直播场次」模块(从主菜单不再可见,通过列表行进入)。

## 6. 功能详细说明

### 6.1 场次列表

#### 6.1.1 顶部操作
- 导出列表 / 多场对比(占位) / 创建场次。

#### 6.1.2 筛选区
| 字段 | 控件 | 说明 |
| --- | --- | --- |
| 日期 | 日期范围选择 | 默认本月 |
| 场次类型 | 下拉 | 全部 / 下午场 / 晚间场 |
| 主播 | 可搜索下拉(datalist) | 支持主播昵称模糊搜索 |
| 店铺类型 | 下拉 | 全部 / 自营 / 入驻 |
| 店铺 | 下拉 | 按店铺类型联动过滤 |

#### 6.1.3 状态 Tab
全部 / 已结束 / 直播中 / 待开播,各显计数。

#### 6.1.4 表格列
| 列 | 内容 |
| --- | --- |
| 直播场次 | 日期 + 时段 + 类型标签(下午场/晚间场) |
| 状态 | 已结束 / 直播中 / 待开播 |
| 场次主题 | 长文本,可换行 |
| 店铺 | 店铺名 + 编号 |
| 人员 | 主播 + 助手 |
| 观看互动 | 观看人数 / 人次 / 互动人数 |
| 上架/支付/支付率 | 件数 + 比率,可排序 |
| 支付总计/成本/成本利润率 | 金额 + 成本 + 利润率(可排序) |
| 操作 | 详情 / 回放 / 导出(直播中显示「实时 / 控制台」) |

整行可点击进入详情。直播中行加底色突出。

### 6.2 场次详情

#### 6.2.1 顶部场次基础信息
4 列卡片:直播时间(起止 + 时长) / 本场人员(主播 / 助手 / 运营) / 直播店铺(名/编号/类型) / 简介公告。

#### 6.2.2 操作栏
导出本场数据 / 查看直播回放 / 数据更新时间(右侧)。

#### 6.2.3 核心数据(L0)
左侧大卡片:**支付总额 + 大金额数字**;
右侧 4 个紧凑指标:成本利润率 / 支付商品件数 / 支付成本 / 支付利润;
每个指标可点 ⓘ 看口径。

#### 6.2.4 全链路转化漏斗(L1)
4 阶段 pipeline:**上架 → 加购 → 下单 → 支付**;
每阶段:阶段名 + ⓘ口径 + 转化率(基于上架分母) + 主指标数 + 副指标(金额 / 客户数 等);
支付阶段品牌色高亮。

#### 6.2.5 本场货品明细
- 筛选:品牌 / 分类 / 成色 / 商品类型 / 商品状态 / 店铺 / 店铺货编 / 日期范围;
- 表格列:商品信息(图片 + 名称 + 属性) / 直播信息(上架时段 / 主播 / 助手 / 起拍价) / 商品价格(成本 / 售价 / 利润率) / 商品类型(拍卖 / 一口价) / 商品状态(已支付 / 已下单 / 已中拍 / 已取消 / 流拍) / 出价数据 / 加购用户 / 客户拓展人 / 操作;
- 支持导出商品。

### 6.3 直播商品(跨场次统计)

#### 6.3.1 筛选区(更细致)
日期 / 品牌 / 分类 / 成色 / 商品类型 / 商品状态 / 主播 / 店铺类型 / 店铺。

#### 6.3.2 支付汇总条(置顶)
4 列横排:支付商品金额 / 支付商品成本 / 支付利润 / 成本利润率,每项带 ⓘ。

#### 6.3.3 货品统计(漏斗 4 卡片)
上架 → 加购 → 下单 → 支付,每张卡片显示件数 + 占比 + 副指标(总额 / 用户数 / 拍卖与一口价拆分)。支付卡片高亮。

#### 6.3.4 货品列表
列与「本场货品明细」一致,但是跨场次的合集。

### 6.4 口径说明弹窗(全局组件)

- 触发:点击任意指标右侧 ⓘ 图标;
- 行为:弹层定位到点击点右侧 + 8px,溢出右边界则翻转左侧;
- 内容:`title` + `body`,body 多行段落支持;
- 关闭:点击关闭按钮 / 点击遮罩 / 按 ESC;
- 已弃用口径用「(已弃用)」前缀标注(如 `kp-fav` 新增收藏)。

## 7. 数据需求

### 7.1 主要实体

**live_session(场次)**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| session_id | string | 主键 |
| title | string | 场次主题 |
| date | date | 直播日期 |
| start_at / end_at | datetime | 起止 |
| duration | seconds | 时长(冗余字段,后端算) |
| type | enum | noon(下午场) / night(晚间场) |
| status | enum | upcoming / live / ended |
| shop_id | string | 店铺 |
| shop_type | enum | 自营 / 入驻 |
| anchor | string | 主播 |
| assistant | string | 助手 |
| operator | string | 运营 |
| notice | text | 简介公告 |

**live_session_stat(场次统计 - 按 T+0 计算)**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| session_id | string | 关联场次 |
| shelf_count | int | 上架件数 |
| shelf_amount | decimal | 上架总额 |
| addcart_count | int | 加购件数 |
| order_count / order_amount | int / decimal | 下单 |
| pay_count / pay_amount / pay_cost / pay_profit | int / decimal | 支付 |
| uv / pv / interact_uv | int | 观看与互动 |
| cancel_count | int | 中拍超时取消 |
| pay_user_count | int | 付费用户(去重) |
| updated_at | datetime | 数据更新时间 |

**live_goods(直播商品)**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| goods_id / sku | string | — |
| brand / category / condition | string / enum | 品牌 / 分类 / 成色 |
| type | enum | auction(拍卖) / fixed(一口价) |
| status | enum | paid / ordered / won / cancelled / unsold |
| session_id | string | 上架场次 |
| anchor | string | 上架主播 |
| start_price / final_price / cost | decimal | 起拍价 / 成交价 / 成本 |
| bid_count / addcart_users | int | 出价次数 / 加购用户数 |
| developer | string | 客户拓展人 |

### 7.2 数据更新策略
- T+0 准实时:每 5 分钟批量从订单 / 支付 / 出价系统聚合(本期);
- 详情页头部展示「数据更新于 <timestamp> · T+0 实时」;
- 售后退回不扣除(口径明确)。

### 7.3 列表字段精简
- 列表 handler 须 strip 大字段(商品 attributes / 主图原图 / 出价明细),仅返回缩略信息;
- 详情请求才返回完整字段。

## 8. 权限

| 操作 | 角色 |
| --- | --- |
| 查看列表 / 详情 / 商品统计 | 全员 |
| **成本 / 利润相关字段**(支付成本 / 支付利润 / 成本利润率) | admin / boss / 财务 / 估价师(参考价格脱敏规则) |
| 导出 | admin / boss / 运营主管 |
| 创建场次 / 编辑公告 | admin / 直播运营 |

成本与利润字段在普通主播 / 助手角色下脱敏为 `--`,避免数据敏感泄露。

## 9. 流程图

```
开播前:运营创建场次 → 配置主播/助手/店铺/上架商品 →「待开播」
   │
开播:状态 → live,实时入累 UV/PV/出价/加购
   │
结束:状态 → ended,T+0 聚合写入 stat 表
   │
复盘:列表 → 点击行 → 详情看 L0 + 漏斗 + 货品明细
       或:直播商品模块跨场筛选汇总
   │
导出:导出本场 / 商品 / 统计数据
```
